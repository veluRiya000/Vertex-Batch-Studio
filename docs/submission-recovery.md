# 生图提交失败恢复

本地源码中的恢复入口位于任务卡片原“刷新结果”区域。正常生成及完成后仍显示“刷新结果”，完成后保留重新解码。

| 状态 | 操作 |
| --- | --- |
| 上传失败、明确提交失败 | 重新提交本轮 |
| 提交结果不明 | 核对并重试 / 仅核对 |
| 查询成功但未找到 | 重新提交本轮（先再次核对，找到原作业则接回） |
| 查询失败 | 重试核对 / 仍要重新提交 |
| 找到多个作业 | 重试核对，或通过已有 attach 接口绑定具体作业，不自动创建 |

“仍要重新提交”在卡片内展示重复任务与费用提示，点击确认后才允许在未核实原作业的情况下重发。恢复复用本轮冻结的提示词、参数和参考图快照，不复制成另一条对话。

## 本机接口

`POST /batches/{batch_id}/recover`

```json
{"confirm_duplicate_risk": false}
```

返回 `202` 和 `{ "queued": true|false, "batch_id": "..." }`。`false` 表示该轮已经有操作，不会再次排队。仅核对仍使用已有 `/poll`。确认风险时发送 `confirm_duplicate_risk: true`，在上一轮查询失败的情况下跳过重复等待并重新提交。该接口仍要求本机应用令牌；归档、已有云端编号、非恢复状态等保护仍适用。

列表、单批次和事件快照新增：`reconciliation_status`、`last_checked_at`、`active_action`、`action_started_at` 和 `operation`。活动操作由当前进程维护，不从磁盘误恢复为运行中；上传/查询阶段信息持久化以便展示和诊断。

## 时限与记录

- 云端作业查询调用方最多等待约10秒；SDK读取在独立、数量受限的守护线程中进行，同批次仍在进行的查询会复用，避免反复点击堆积线程。超时查询仅做远端读取，不持有仓库对象或在结束后偷偷创建作业。
- 单页查询网络超时8秒；创建作业请求超时20秒。
- GCS元数据单次请求10秒、重试窗口15秒；上传请求30秒、重试窗口40秒。这些上传配置并不等于所有文件合计的总期限，大文件上传仍按实际进度显示。
- 能明确识别的连接建立失败归为可重试提交失败；读取响应EOF等不确定异常保留核对入口。
- 不再让用户等待10分钟后进入无恢复出口的灰色状态；查询结束后明确区分未找到、查询失败和多个匹配。
- 记录异常类型和原因链，避免空异常文本丢失线索。真正收到作业结果之后的本地落盘异常不归类为连接建立失败。

## 验证

离线模拟覆盖：上传失败重试、连接建立失败、已接受作业后的响应丢失、查询失败、显式风险重试、多个匹配、重复点击及查询截止。使用真实Google SDK的MockTransport验证序列化。浏览器界面验证恢复原轮次、保留提示词、行内确认和正常刷新结果。

此变更未创建真实云端作业，未修改用户已有批次数据。现有安装版需要重新构建后才能加载新的后端和桌面接口白名单；本次不自动发布GitHub版本。
