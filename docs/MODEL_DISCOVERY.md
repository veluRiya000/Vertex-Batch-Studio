# 冷启动模型发现

应用冷启动时，后端启动一次后台同步；界面初始化也调用同步接口，以覆盖桌面端复用已有后端的情况。并发刷新合并为一次，窗口启动、健康检查和退出不等待联网。最晚约 45 秒得到同步结果；网络读取有独立超时、响应大小限制、官方域名校验及重定向限制。

## 权威数据来源和筛选

读取 [Google 官方 Vertex Gemini 批量支持目录](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/multimodal/batch-prediction-gemini?hl=en)，完整遍历该正文支持章节中的模型链接，再读取每个官方模型能力页。模型 ID、显示名称、区域、图像输出能力、批量支持、生命周期、比例和参考图限制来自这些页面，不使用模型 ID 白名单，也不因名字包含 image 就收录。

只收录符合本项目 Gemini `contents` / `generationConfig` JSONL 请求和响应协议的模型。Imagen、Veo、Embedding、只支持图像输入或不支持批量的模型不会加入。能力页明确不支持 GenerateContent 的模型被排除；部分新能力页省略 API 栏，使用官方 Gemini 批量目录所规定的公共请求协议作为兼容依据。

Model Garden 的 PublisherModel 元数据没有同时提供足够的图像输出与批量推理能力标记，因此本实现使用公共权威文档目录。该目录是完整 HTML 文档，没有 pageToken；实现遍历正文中的全部模型链接、去重，并拒绝异常空目录/超过 100 项的目录，避免只读取第一页或导航侧栏。

模型必须支持当前 `GOOGLE_CLOUD_LOCATION`。不自动更换区域；官方确切退休日期到期、标记 Deprecated/Retired/Discontinued、从批量支持目录删除、返回 404/410、或不再支持批量/图像输出时，成功刷新得到的完整集合会替换旧集合。若官方日期写明“or later”，不把最早可能日期误判成确定下线日。

文档格式不明确、部分页面无法访问、权限错误、网络错误或超时都属于刷新失败，不发布部分模型集合。公共目录不需要服务账号或 ADC，因此缺少凭据不会阻止发现。实际项目 IAM、服务启用、配额、服务代理权限仍由现有云端连接及提交逻辑处理；公共文档不能保证某个账号获得所有模型的调用权限。发现流程不创建付费预测任务。

## 缓存和回退

- 成功结果原子写入 `data/model-catalog/<project+location 的 SHA256>.json`（实际基于 `VBS_DATA_DIR`），包括来源、时间及能力字段。不同项目和区域使用不同缓存文件。
- 冷启动总是联网刷新，不因缓存较新而跳过。最近 30 天的成功缓存可先显示；失败时显示“模型缓存”，并保留最近成功结果。过期、损坏、范围不匹配或关键能力字段无效的缓存被忽略。
- 成功发现零个模型也是有效结果（例如区域不支持），会持久化空集合；不会把旧模型合并回来。已知确切退休日期在断网时仍生效。
- 没有有效缓存且刷新失败时，动态下拉选项为空，显示“模型未验证”，保留原配置模型用于兼容已有工作流；不会冒充它是已验证动态模型。首次同步尚未完成且没有缓存时，新的提交会提示稍后重试。
- 当前选中模型从目录移除后，仍保留它的配置 ID 以便用户看见变化，但它不会作为可选项混入目录。已确认目录下的新草稿提交要求选择目录中的可用模型，不静默切换到其他模型。

## 选择和任务兼容

选择结果保存到 `.runtime/model-selection.json`，按项目及区域恢复；保留 `.env` 中的 `VERTEX_MODEL` 作为初始配置。切换不会改写已经准备或已经提交批次的 `inputs/manifest.json`、JSONL、云端任务 ID 和图片记录。已有云端任务按原 manifest 的模型继续查询和下载。后台批次操作尚未完成时拒绝切换，避免排队提交和选择操作发生竞争。

新准备的批次使用实际选中的模型。官方当前批量指南限制图像输出为 1K，因此已确认模型在界面仅提供 1K 选项，后端也验证分辨率、已知比例和参考图数量。对没有显式分辨率控制的模型（例如当前 Gemini 2.5 Flash Image）省略 `imageSize`，使用默认 1K。旧任务数据不会自动改写，已准备快照不会自动重建。

## 本地接口

Nano Banana 2.1 的参数限制按 [Google 官方说明](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/nano-banana-2-1)执行：生成最终请求时省略 `temperature`、`topP`、`topK`、`seed`、`logprobs`，同时省略关联的 `responseLogprobs` 开关。过滤发生在任务输入的副本上，不改写 `tasks.json`，其他模型仍保留原参数。模型能力页的 Parameter defaults 栏也会提取已明确不支持的参数，供以后型号复用；2.1 的已知限制作为协议兼容规则，在断网和旧缓存时仍然生效。

界面通过 `/config` 的 `unsupported_generation_parameters` 获取当前模型限制，2.1 的温度按钮禁用并显示“不支持”。新 2.1 任务不保存自定义温度；编辑旧任务时保留原温度记录，切回支持温度的模型恢复原选择。

修复前的已准备快照如果含受限参数，提交前返回明确提示，且不上传或创建云端任务；请重新准备，输入已冻结时建立新批次。已经提交或提交结果尚未确认的任务继续使用原快照查询/恢复，不自动重写或重复提交。

所有接口沿用本机令牌验证，桌面端白名单已同步更新。

| 接口 | 行为 |
| --- | --- |
| `GET /config` | 新增 `model_catalog`，含模型列表、official/cache/unavailable 来源、refreshing、fetched_at、message |
| `POST /models/refresh` | 发起非阻塞、合并并发的刷新，返回当前配置；通过 `/config` 读取完成结果 |
| `POST /models/selection` | 请求 `{ "model": "目录中的模型 ID" }`，保存选择并返回配置；未知模型返回 400，操作竞争返回 409 |

界面每五秒读取本地状态，不每五秒访问 Google。完整退出后重新启动会重新访问官方目录。

## 验证

`tests/test_model_catalog.py` 覆盖未知未来模型、完整链接遍历、图像输入排除、批量/API 不兼容、区域、弃用与退休日期、页面结构错误、导航隔离、整体超时、部分 403、成功空集合、断网缓存、损坏/过期/未来缓存、缓存写入失败、冷启动重新刷新、并发与退出、认证选择、持久化、排队操作竞争、旧 manifest 保持和新请求兼容。

2026-10-14 实际官方目录验证：`global` 自动发现五个图像批量模型，包含 `gemini-nano-banana-2.1`，无需修改模型白名单。后端 97 项、前端 40 项、Rust 2 项测试通过，TypeScript 检查与前端生产构建通过。未创建真实付费生图任务。

修改的是本机项目源码。已安装或另行分发的桌面安装包需重新打包才会包含本次改动。
